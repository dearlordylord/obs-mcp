## Actionable gaps

| Priority | Area | Finding | Recommended next move |

| P1 | Filter settings | Roy returns OBS filter setting objects and passes arbitrary JSON records into `SetSourceFilterSettings` ([pinned implementation](https://github.com/royshil/obs-mcp/blob/314e7c065ef8c5e2656757b35b24ea7fa81489b0/src/tools/filters.ts#L274-L292)). Our reads deliberately reduce each setting to name/type and mark raw values deferred, while writes accept exactly `brightness`, `contrast`, `gamma`, `saturation`, `hueShift`, `opacity`, `colorMultiply`, `colorAdd`, and `db` ([current schema](https://github.com/dearlordylord/obs-mcp/blob/587e356b00d9269dcd124969ee36aad9635f2db8/src/domain/schemas/filters.ts#L34-L77), [write allowlist](https://github.com/dearlordylord/obs-mcp/blob/587e356b00d9269dcd124969ee36aad9635f2db8/src/domain/schemas/filters.ts#L112-L167)). This blocks other built-in controls such as crop geometry, compressor parameters, and LUT/file settings, as well as plugin-defined keys. | Add an opt-in JSON-safe filter settings read/write path, or expand by discovered filter kind. Preserve exact-locator validation and structured outputs. This is the highest-value parity fix. |
| P1 | Output settings | Roy exposes the whole `outputSettings` object for get/set ([pinned implementation](https://github.com/royshil/obs-mcp/blob/314e7c065ef8c5e2656757b35b24ea7fa81489b0/src/tools/outputs.ts#L464-L507)). Document that keys are output-kind specific. |
| P2 | Current transition settings | Roy *attempts* a dedicated `GetCurrentSceneTransitionSettings` request and accepts arbitrary settings on set ([pinned implementation](https://github.com/royshil/obs-mcp/blob/314e7c065ef8c5e2656757b35b24ea7fa81489b0/src/tools/transitions.ts#L190-L235)). ## Equivalent or intentionally different

- **Screenshots are functionally ahead overall.** Roy's read returns only the first 100 characters of `imageData`, so a caller cannot reconstruct the image; its save tool accepts any filesystem path ([pinned source](https://github.com/royshil/obs-mcp/blob/314e7c065ef8c5e2656757b35b24ea7fa81489b0/src/tools/sources.ts#L66-L117)). We return the complete base64 payload with MIME/byte metadata and enforce a size bound, while saves require an existing configured directory and a simple filename ([current operation](https://github.com/dearlordylord/obs-mcp/blob/587e356b00d9269dcd124969ee36aad9635f2db8/src/obs/operations/screenshots.ts#L49-L96)). Arbitrary save paths are an intentional policy difference, not a feature gap.
- **`obs-sleep` should not be copied.** Roy exposes it as a standalone tool, but OBS defines `Sleep` for serial realtime/frame request batches ([pinned protocol](https://github.com/obsproject/obs-websocket/blob/ffb09e892bb829e781172a2883870aa1416c638c/docs/generated/protocol.md#L2983-L3022)). Our constrained `run_obs_request_batch` is the correct semantic home.
- **`obs-get-status` and `obs-test-connection` are conveniences, not protocol gaps.** Roy added them only in the repository after the published 125-tool package; `obs-test-connection` repeats `GetVersion`, while status reports local connection fields ([pinned general tools](https://github.com/royshil/obs-mcp/blob/314e7c065ef8c5e2656757b35b24ea7fa81489b0/src/tools/general.ts#L6-L117)). Our `get_version`, sanitized `get_obs_context`, reconnecting client, and state resource cover the underlying needs. A single connected-state field could improve ergonomics, but it should not outrank settings completeness.
- **Default visibility is a policy choice.** Roy registers all tools unconditionally. We filter by configured toolset and by OBS's advertised requests ([current registry](https://github.com/dearlordylord/obs-mcp/blob/587e356b00d9269dcd124969ee36aad9635f2db8/src/mcp/tools/mechanics.ts#L74-L87)); opt-in config, filesystem, vendor, event, and batch surfaces therefore do not count as missing features.
- **Enabling every toolset does not cover the settings gaps.** `TOOLSETS=all` exposes filters, outputs, config, transitions, and screenshots, but their schemas still enforce the restrictions above. There is no arbitrary official OBS request escape hatch in current source: `admin_raw` is limited to persistent-data slots, and `vendor` is limited to plugin vendor requests. The older architecture draft's proposed `send_raw_obs_request` was never implemented. The P1 gaps therefore need explicit tools or deliberate JSON-safe extensions.

## Areas where current implementation is ahead

Beyond the larger 159-tool surface, current source adds capabilities Roy lacks: canvas-aware identities; group, duplicate, lock, index, and blend-mode scene-item operations; input audio tracks/deinterlace/property discovery/buttons; T-bar and transition cursor; typed bounded event history and confirmation workflows; MCP resources with update notifications; Streamable HTTP with optional bearer authentication; capability-gated registration; strict input/output schemas and structured content; bounded screenshot payloads and path policy; and a substantive fake/real OBS test harness. Roy's pinned source has only a CLI-existence test and emits most results as textified JSON ([pinned test](https://github.com/royshil/obs-mcp/blob/314e7c065ef8c5e2656757b35b24ea7fa81489b0/src/index.test.ts), [pinned tool example](https://github.com/royshil/obs-mcp/blob/314e7c065ef8c5e2656757b35b24ea7fa81489b0/src/tools/outputs.ts#L464-L520)).

## Decision

Roy has not moved since the previous review, so no reactive roadmap change is needed. Schedule the two generic-settings gaps first: filter settings, then output settings. Include `transitionSettings` in the existing current-transition read in the same tranche if small. Keep the screenshot filesystem boundary and batch-only Sleep policy; only make screenshot formats capability-driven. Recheck Roy by branch SHA and npm metadata in the next competitor sweep, since its repository and published-version metadata are already out of sync.
