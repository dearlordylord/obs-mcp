## What to build

A fresh consumer runs a real MCP process and proves existing inspection, mutation/readback, audio, recording and screenshot behavior.

## Acceptance criteria

- [ ] Extend the existing package-smoke seam to install a supplied tarball into a clean consumer and connect to a maintained controlled OBS endpoint.
- [ ] Verify scene inspection and mutation/readback, audio state, recording start/stop and complete existing screenshot bytes against independently observed fixture state.
- [ ] Record artifact identity, source/lock provenance, explicit configuration and timeouts in the report; clean up child processes and fixture resources.
- [ ] Keep acceptance infrastructure outside historical benchmark snapshots; use a valid independently decodable image fixture.
- [ ] Treat known pending feature gaps as explicit pending contracts, never passed tests; do not change production features to inflate the baseline.
