## Parent

[Provide explicit full-fidelity filter, output, and transition settings contracts](https://github.com/dearlordylord/obs-mcp/issues/10)

## What to build

Users inspect the active transition's settings and apply supported nested updates.

## Acceptance criteria

- [ ] Expose transitionSettings through the existing valid current-transition request; never introduce a nonexistent getter.
- [ ] Verify packaged nested read/update/readback with arrays, unknown permitted keys and unrelated settings retained or replaced according to the official contract.
- [ ] Keep typed convenience responses compatible and enforce the recorded limits, exclusions and explicit-access policy.
- [ ] Test malformed input, unavailable capability and OBS rejection with independent state assertions.
- [ ] Document write semantics and reuse shared settings validation without a universal raw dispatcher.
- [ ] Apply recursive value limits and sensitive-field rules on both reads and writes, including nested arrays/objects; excluded data is explicitly marked rather than described as lossless.
