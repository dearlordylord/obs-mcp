## Parent

[Establish OBS adoption contracts, current baseline, and maintained acceptance fixture](https://github.com/dearlordylord/obs-mcp/issues/8)

## What to build

Acceptance fails when the server reports success without the expected OBS state, and reports faults without inventing a verdict.

## Acceptance criteria

- [ ] Exercise OBS rejection, unavailable capabilities, timeouts and disconnects through installed MCP; record that each intended fault was actually injected and observed.
- [ ] Distinguish confirmed state changes, failed changes, unknown outcomes and fixture-unimplemented requests; no unexercised fault or unsupported fixture case counts as acceptance success.
- [ ] Handle valid contract-supported text/structured result forms; reject success-shaped responses when independently observed state disagrees.
- [ ] Prove malformed image data is rejected by the acceptance oracle and timeout watchdogs leave a documented observation margin.
- [ ] Preserve and verify existing no-replay behavior for uncertain mutations and batches; use focused protocol tests for applied-but-reply-lost cases where needed.
