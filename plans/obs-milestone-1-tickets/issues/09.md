## Parent

[Provide explicit full-fidelity filter, output, and transition settings contracts](https://github.com/dearlordylord/obs-mcp/issues/10)

## What to build

Explicit settings access preserves permitted nested filter values while existing typed controls keep working.

## Acceptance criteria

- [ ] Implement the recorded explicit settings read/write contract end to end, including unknown permitted keys, arrays, objects, null and finite primitives.
- [ ] Verify packaged read/update/readback against nested plugin-style fixture state and independently observed changes.
- [ ] Enforce documented size/depth bounds, opt-in policy and sensitive-field exclusions; show exclusions rather than imply an exact round trip.
- [ ] Preserve typed convenience behavior and per-request merge/replacement semantics without unsafe read-modify-write.
- [ ] Test malformed values, OBS rejection and missing capability through public boundaries; update contract documentation.
- [ ] Apply recursive value limits and sensitive-field rules on both reads and writes, including nested arrays/objects; excluded data is explicitly marked rather than described as lossless.
- [ ] Define explicit full-fidelity access for specific filter settings reads and writes; record whether list/default reads retain sanitized summaries and preserve their compatibility. Do not broaden every filter response implicitly.
