## Parent

[Return native MCP images and define remote screenshot save semantics](https://github.com/dearlordylord/obs-mcp/issues/11)

## What to build

Users know which host receives a saved screenshot and receive truthful results for supported topologies.

## Acceptance criteria

- [ ] Implement the recorded local/shared/remote topology contract; never use an MCP-host path check as proof that remote OBS can write.
- [ ] Retain filename/directory boundaries and document any explicit shared-filesystem assumption or unsupported topology.
- [ ] Use a controlled endpoint with differing host path assumptions to verify outgoing destination and honest save success/error handling.
- [ ] Preserve bounded retention and existing capture metadata behavior; document supported formats and limits.
- [ ] Supply a reproducible save-topology check for subsequent real OBS acceptance without claiming the fixture proves a real file was written.
- [ ] Cover traversal, missing configuration, a valid OBS-host destination absent on the MCP host, and OBS save rejection; distinguish acknowledgement from independently verified file existence.
- [ ] Define whether saved:true denotes OBS completion acknowledgement or independently observed file existence; interpret path syntax and resolution only for the declared OBS-host topology.
