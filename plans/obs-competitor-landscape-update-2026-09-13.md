# OBS MCP competitor landscape update

Date checked: 2026-09-13  
Baseline: the 2026-06-14 snapshots in [`.references/competitors/INDEX.md`](../.references/competitors/INDEX.md)  
Scope: established OBS Studio competitors other than `royshil/obs-mcp`, which is being reviewed separately.

## Result

The direct competitors did not ship a new OBS/MCP feature surface after the June snapshot. `cdavis-code/obs_websocket_workspace` improved installation substantially with native binaries and Homebrew; `sbroenne/mcp-server-obs` received dependency maintenance; the remaining direct competitors were dormant.

The largest product change came from adjacent competitor `JulienCr/obs-live-suite`. It added a work-in-progress, human-approved Live Assist pipeline that listens to studio audio, detects configured topics, asks an LLM to extract intent, and proposes poster or definition actions to an operator. That is a meaningful workflow lead, but its MCP server itself did not change.

Against the current source, this project is not behind on low-level obs-websocket breadth. It has 159 explicit MCP tools, 14 static resources plus 5 templates, stdio and Streamable HTTP transports, and local descriptors for all 147 official requests and all 60 official events. The material gaps exposed by this refresh are distribution convenience and an optional production-assistance layer.

## Comparison with the current project

The June gap labels are obsolete for the local implementation. The current [`README.md`](../README.md#available-tools) publishes 159 explicit tools in 16 toolsets. It includes full scenes and scene-item control, raw input settings discovery and mutation, filters, media, generic outputs, virtual camera, replay buffer, recording, streaming, transitions, UI, screenshots, request batches, vendor requests, safe event history, and typed event confirmation workflows. The [resource catalogue](../README.md#resources) adds 14 static resources and 5 resource templates with update subscriptions over stateful HTTP. Running `pnpm audit-protocol-parity` on 2026-09-13 reported 147 official requests with 147 local descriptors and 60 official events with 60 local catalogue entries, with no missing entries.

The post-snapshot competitive changes therefore map to two real gaps:

1. **Native distribution.** `@firfi/obs-mcp@0.3.3` is easy to run through `npx` and documents major MCP clients, but it does not offer prebuilt native binaries, Homebrew, or a VS Code extension. The cdavis release makes native binaries/Homebrew the clearest newly widened gap. A native package should be justified by installation/support demand because `npx` already provides a cross-platform path.
2. **Assisted live-production workflows.** OBS Live Suite now turns ambient studio speech into reviewable overlay/content suggestions. Our current server supplies the reliable low-level operations, resources, and confirmations needed by an external agent, but it does not package transcription, intent extraction, domain providers, or a human approval queue. If this product moves above protocol control, the smallest useful experiment is a generic suggestion/approval workflow that invokes existing typed tools; bundling STT, GPU dependencies, and poster providers into the core MCP server would couple unrelated concerns.

Two existing distribution/product differences remain visible but did not widen during this period: Sbroenne's VS Code extension and Agentic OBS's dashboard/TUI/prompts. They should stay on the watchlist rather than be reported as newly discovered regressions.

## Recommended watch points

- Watch `cdavis-code/obs_websocket_workspace` releases for new generated OBS operations; its September head is active even though this period's changes were packaging and maintenance.
- Watch whether OBS Live Suite promotes Live Assist from WIP, removes its NVIDIA-only constraint, adds more action providers, or exposes the assistance queue through MCP. Any of those would strengthen it as a direct agent-workflow competitor.
- Recheck the dormant repositories by commit SHA rather than repository `updated_at`, which can change because of metadata without a source commit.
- Treat native binary/Homebrew packaging as the only immediate competitive follow-up. Treat an assisted-production layer as a separate product decision, not a protocol-parity requirement.

## Method

This refresh compared every saved June SHA with the default branch through the GitHub compare and commit APIs, checked GitHub releases/tags, and queried npm package metadata where a package exists. Feature conclusions use repository-owned commits, source trees, READMEs, and release pages. Competitor code was inspected only; it was not executed or copied into this implementation.
